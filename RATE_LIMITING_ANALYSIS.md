# 🔍 Анализ проблемы rate limiting для AI API

## 📋 Проблема из логов

Множественные ошибки 429 (Too Many Requests) для Gemini и OpenAI API.

---

## 🔍 ДЕТАЛЬНЫЙ АНАЛИЗ

### Текущая логика AI анализа:

#### 1. При парсинге RSS (`scheduled_parsing`):

```python
# Предварительный расчет приоритета БЕЗ AI
priority_quick = PriorityCalculator.calculate_priority(news, None)

# AI анализ ТОЛЬКО для потенциально важных новостей (priority >= 6)
ai_analysis = None
if priority_quick >= 6:
    ai_analysis = await ai_analyzer.analyze_text(...)

# Финальный расчет приоритета (с учетом AI если был выполнен)
priority = PriorityCalculator.calculate_priority(news, ai_analysis)
```

**Проблема:** Результат `ai_analysis` используется только для расчета priority, но НЕ сохраняется в БД!

---

#### 2. При публикации (`check_queue_and_post`):

```python
# Подготовка данных
ai_data = None
try:
    if "Insider" in news_item['source']:
        ai_data = await ai_analyzer.analyze_text(...)
    else:
        ai_result = await ai_analyzer.translate_and_analyze(...)
        if ai_result:
            news_item['title'] = ai_result.get('clean_title', ...)
            news_item['summary'] = ai_result.get('clean_summary', ...)
            ai_data = ai_result
```

**Проблема:** AI анализ вызывается ЗАНОВО, даже если уже был выполнен при парсинге!

---

## 🔴 ИТОГО: ДВОЙНОЙ ВЫЗОВ AI API

1. **При парсинге RSS:** AI анализ для новостей с priority >= 6
2. **При публикации:** AI анализ для ВСЕХ публикуемых новостей

**Результат:** 
- Новость анализируется дважды
- Двойное количество запросов к API
- Превышение квоты

---

## 🔧 ВАРИАНТЫ РЕШЕНИЯ

### Вариант 1: Убрать AI анализ из парсинга RSS (РЕКОМЕНДУЕТСЯ)

**Логика:**
- При парсинге RSS: НЕ вызывать AI анализ (только keyword-based priority)
- При публикации: Вызывать AI анализ для перевода и улучшения

**Плюсы:**
- Простая реализация
- Меньше запросов к API
- AI анализ только когда нужно (перед публикацией)

**Минусы:**
- Priority при парсинге менее точный (но это не критично)

---

### Вариант 2: Сохранять AI анализ в БД

**Логика:**
- При парсинге RSS: Вызывать AI анализ и сохранять результат в БД
- При публикации: Использовать сохраненный результат из БД

**Плюсы:**
- Более точный priority при парсинге
- Не нужно вызывать AI анализ дважды

**Минусы:**
- Нужно добавить поле в БД для AI анализа
- Более сложная реализация
- Больше данных в БД

---

### Вариант 3: Добавить rate limiting (дополнительно)

**Логика:**
- Добавить задержки между запросами к AI API
- Ограничить количество одновременных запросов

**Плюсы:**
- Защита от 429 ошибок
- Более стабильная работа

**Минусы:**
- Не решает проблему двойного вызова
- Замедляет обработку

---

## 🎯 РЕКОМЕНДУЕМОЕ РЕШЕНИЕ

**Комбинация Варианта 1 + Варианта 3:**

1. ✅ Убрать AI анализ из парсинга RSS
2. ✅ Оставить AI анализ только при публикации
3. ✅ Добавить rate limiting для AI API (задержки между запросами)

**Реализация:**
- Убрать блок `if priority_quick >= 6: ai_analysis = ...` из `scheduled_parsing`
- Добавить простой rate limiter с задержкой 1-2 секунды между запросами
