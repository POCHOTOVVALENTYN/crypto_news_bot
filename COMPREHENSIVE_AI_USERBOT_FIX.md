### 1.1. Проблема с именем модели Gemini

**Файл:** `services/ai_summary.py`, строка 42

**Текущий код:**
```python
model_name = 'gemini-1.5-flash'
```

**Проблема:** 
- Модель `gemini-1.5-flash` возвращает 404 для API v1beta
- Согласно документации, нужно использовать другое имя или другой API endpoint
- Возможно нужно использовать `gemini-2.5-flash` или другой формат

**Решение:**
- Попробовать несколько вариантов имен моделей
- Добавить fallback механизм
- Улучшить логирование ошибок

---

### 1.2. Проблема с фильтрацией в process_incoming_news

**Файл:** `services/ai_summary.py`, строка 179

**Текущий код:**
```python
if result and result.get('importance') == 'High':
    return result
return None
```

**Проблема:**
- Фильтрует ТОЛЬКО новости с `importance == 'High'`
- Но AI возвращает: "Critical", "Very High", "High", "Medium", "Low"
- Это слишком строгая фильтрация - пропускает "Critical" и "Very High"!
- Для Userbot (Insider новостей) это критично - важные новости отфильтровываются

**Решение:**
- Проверять на несколько значений: "High", "Very High", "Critical"
- Или использовать `importance_score` (числовое значение)
- Или убрать фильтрацию совсем для Userbot

---

### 1.3. КРИТИЧЕСКАЯ ОШИБКА: Priority для Insider новостей = 1

**Файл:** `services/telegram_listener.py`, строка 228

**Текущий код:**
```python
priority=1  # Молния!
```

**Проблема:**
- Priority = 1 для Insider новостей - это КРИТИЧЕСКАЯ ОШИБКА!
- Priority = 1 - это НИЗКИЙ приоритет (почти отфильтровывается)
- Комментарий говорит "Молния!" но это неправильно
- Insider новости должны иметь priority = 10 (максимальный)
- В PriorityCalculator есть логика: `if 'insider' in source: priority = 10`, но она не работает потому что priority уже установлен в 1

**Решение:**
- Изменить priority = 10 для Insider новостей

# 🔴 ПРОБЛЕМА 2: USERBOT

## Из логов:

```
RuntimeError: 3 consecutive sign-in attempts failed. Aborting
TG_SESSION_STRING=None
Please enter your phone (or bot token):
```

## Детальный анализ кода:

### 2.1. Проблема с миграцией сессии

**Файл:** `services/telegram_listener.py`, строки 33-74

**Проблема:**
- Миграция выполняется при каждом запуске бота
- Если миграция не удается (сессия не валидна), возвращается пустая сессия
- Пустая сессия → требуется интерактивная авторизация → невозможно в фоне

**Решение:**
- Упростить логику миграции
- Пропускать миграцию если она не работает
- Требовать ручную настройку сессии через отдельную команду

---

### 2.2. Проблема с интерактивной авторизацией

**Файл:** `services/telegram_listener.py`, строка 112

**Текущий код:**
```python
await self.client.start()
```

**Проблема:**
- `client.start()` требует интерактивного ввода (телефон, код)
- Это невозможно в фоновом режиме
- Нужна валидная сессия в `TG_SESSION_STRING` перед запуском

**Решение:**
- Проверять валидность сессии перед запуском
- Не запускать если нет валидной сессии
- Предоставить четкие инструкции для создания сессии

---

### 2.3. Проблема с обработкой ошибок авторизации

**Файл:** `services/telegram_listener.py`, строки 158-164

**Проблема:**
- Ошибки авторизации логируются, но бот продолжает работать
- Нет четкого сообщения пользователю о том, что делать
- Функция `setup_userbot()` существует, но не используется

**Решение:**
- Улучшить сообщения об ошибках
- Добавить ссылку на инструкцию
- Упростить процесс настройки
