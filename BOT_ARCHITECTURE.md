## 🔧 Компоненты системы

### 1. **Config (`config.py`)**
**Роль:** Управление настройками бота

**Что делает:**
- Загружает переменные окружения из `.env`
- Валидирует обязательные параметры
- Предоставляет доступ к настройкам через `config`

**Ключевые настройки:**
- `telegram_bot_token` - токен бота
- `telegram_channel_id` - ID канала для публикации
- `admin_id` - ID админа для алертов
- `gemini_api_key` / `openai_api_key` - ключи AI
- `tg_api_id`, `tg_api_hash` - для Userbot
- `source_channels` - каналы для мониторинга

---

### 2. **Database (`database.py`)**
**Роль:** Хранение новостей в SQLite

**Таблица `news`:**
- `id` - уникальный ID
- `url` - ссылка на новость (уникальный ключ)
- `title` - заголовок
- `summary` - краткое описание
- `source` - источник
- `published_at` - дата публикации
- `image_url` - ссылка на изображение
- `priority` - приоритет (0-10)
- `posted_to_telegram` - флаг публикации (0/1)
- `created_at` - время создания записи

**Методы:**
- `init()` - инициализация БД
- `add_news()` - добавление новости
- `news_exists()` - проверка дубликатов
- `get_oldest_unposted_news()` - получение следующей новости
- `get_hot_news()` - получение горячих новостей (priority >= 6)
- `mark_as_posted()` - пометить как опубликованную

---

### 3. **RSS Parser (`parser/rss_parser.py`)**
**Роль:** Сбор новостей из RSS фидов

**Что делает:**
- Парсит RSS фиды известных крипто-сайтов
- Фильтрует по ключевым словам (whitelist/blacklist)
- Возвращает список новостей в едином формате

**Источники:**
- Forklog
- Coinspot
- CoinDesk
- Cointelegraph
- Decrypt
- The Block

**Формат данных:**
```python
{
    'link': 'https://...',
    'title': 'Заголовок',
    'summary': 'Описание',
    'source': 'Forklog',
    'published': '2024-12-30 12:00:00',
    'image_url': 'https://...'
}
```

---

### 4. **Telegram Listener (`services/telegram_listener.py`)**
**Роль:** Мониторинг Telegram каналов (Userbot)

**Что делает:**
- Подключается к Telegram как пользователь
- Слушает указанные каналы
- Фильтрует сообщения (стоп-слова, длина)
- Отправляет важные сообщения в БД с высоким приоритетом

**Источники:**
- @WalterBloomberg
- @RBCCrypto
- @Defiscamcheck
- и другие

**Процесс:**
1. Получает сообщение из канала
2. Фильтрует (стоп-слова, длина)
3. Проверяет дубликаты
4. Анализирует через AI (если важно)
5. Сохраняет в БД с priority = 10 (Insider)

---

### 5. **News Validator (`utils/news_validator.py`)**
**Роль:** Валидация новостей перед сохранением

**Проверки:**
- Длина заголовка (5-500 символов)
- Наличие URL
- Наличие источника
- Подозрительные символы
- Актуальность (не старше 48 часов)

**Методы:**
- `validate_news_item()` - полная валидация
- `is_news_relevant()` - проверка актуальности

---

### 6. **Priority Calculator (`services/priority_calculator.py`)**
**Роль:** Вычисление приоритета новости (0-10)

**Факторы:**
1. **Ключевые слова** (0-10):
   - hack, взлом → 10
   - ETF approval → 9
   - listing → 7-8
   - и т.д.

2. **Влиятельные персоны** (минимум 6):
   - Elon Musk
   - Michael Saylor
   - Gary Gensler
   - и т.д.

3. **Премиум источники** (минимум 3):
   - CoinDesk, Cointelegraph, The Block

4. **AI анализ** (если выполнен):
   - importance_score от AI

5. **Insider источники** (10):
   - Telegram каналы через Userbot

**Логика:**
```python
priority = 0
# 1. Ключевые слова
priority = max(priority, keyword_weight)
# 2. Персоны
priority = max(priority, 6)
# 3. Источники
priority = max(priority, 3)
# 4. AI
priority = max(priority, ai_score)
# 5. Insider
if 'insider' in source: priority = 10
```

### 7. **AI Analyzer (`services/ai_summary.py`)**
**Роль:** AI анализ новостей для определения важности

**Провайдеры:**
- **Gemini** (основной) - `gemini-1.5-flash`
- **OpenAI** (fallback) - `gpt-4o-mini`

**Что делает:**
- Анализирует заголовок и описание
- Определяет важность (0-10)
- Создает русский заголовок и описание
- Определяет тональность (Bullish/Bearish/Neutral)
- Определяет монету (BTC/ETH/SOL/Market)

**Формат ответа:**
```json
{
    "importance": "High",
    "importance_score": 8,
    "ru_title": "Заголовок на русском",
    "ru_summary": "Описание на русском",
    "sentiment": "Bullish",
    "coin": "BTC",
    "market_impact": "High"
}
```

**Когда используется:**
- Для новостей с priority >= 6 (при RSS парсинге)
- Для всех новостей из Userbot (Insider)

---

### 8. **Rate Limiter (`services/rate_limiter.py`)**
**Роль:** Ограничение частоты публикаций

**Логика:**
- Минимальный интервал: 300 секунд (5 минут)
- Следит за временем последнего поста
- Блокирует публикацию если прошло < 5 минут

**Исключения:**
- Горячие новости (priority >= 6) публикуются вне очереди

```
    ↓

    ↓

```

```
    ↓

    ↓

    ↓

    ↓

    ↓
```

```
    ↓

    ↓

    ↓

    ↓

    ↓
db.mark_as_posted() → Пометка как опубликованная
```

## ⏰ Расписание задач

### 1. RSS Parsing
- **Интервал:** каждые 10 минут
- **Функция:** `scheduled_parsing()`
- **Что делает:**
  - Парсит все RSS фиды
  - Валидирует новости
  - Рассчитывает приоритет
  - Сохраняет в БД

### 2. Queue Poster
- **Интервал:** каждые 60 секунд
- **Функция:** `check_queue_and_post()`
- **Что делает:**
  - Проверяет горячие новости (priority >= 6)
  - Проверяет rate limiter
  - Публикует следующую новость

### 3. Health Monitor
- **Интервал:** каждые 10 минут
- **Функция:** `monitor_health()`
- **Что делает:**
  - Проверяет время последнего поста
  - Проверяет статус Userbot
  - Отправляет алерты при проблемах

## 📊 Система приоритетов

### Приоритеты (0-10):

- **10 (Critical):** Insider новости, взломы, банкротства
- **9 (Very High):** ETF одобрения, крупные листинги
- **8 (High):** Регуляторные новости, институциональные инвестиции
- **7 (High):** Листинги, крупные транзакции
- **6 (Medium):** Значимые обновления
- **3-5 (Medium):** Премиум источники, обычные новости
- **1 (Low):** Базовый приоритет для всех валидных новостей
- **0 (None):** Нерелевантные новости (отфильтровываются)

### Логика фильтрации:

- **Priority == 0:** ПРОПУСК (не сохраняется в БД)
- **Priority >= 1:** Сохраняется в БД
- **Priority >= 6:** Горячая новость (публикация вне очереди)
- **Priority >= 6:** AI анализ при RSS парсинге

## 🚀 Процесс запуска бота

### 1. Инициализация (`main.py`)

```
1. Загрузка конфигурации (config.py)
2. Настройка логирования
3. Инициализация компонентов:
   - Bot (aiogram)
   - Database
   - RSS Parser
   - AI Analyzer
   - Rate Limiter
   - Scheduler
4. Настройка AlertManager
```

### 2. Запуск компонентов

```
1. Database.init() → Создание таблиц
2. Userbot.start() → Запуск мониторинга каналов (если настроен)
3. Scheduler.start() → Запуск планировщика
4. Первый запуск задач:
   - scheduled_parsing()
   - check_queue_and_post()
5. Отправка алерта админу о запуске
6. dp.start_polling() → Запуск бота (Long Polling)
```

### 3. Работа бота

```
1. RSS Parsing работает в фоне (каждые 10 минут)
2. Queue Poster работает в фоне (каждые 60 секунд)
3. Health Monitor работает в фоне (каждые 10 минут)
4. Userbot слушает каналы (если запущен)
5. Bot обрабатывает команды (/stats, /health)
```

## 🔍 Ключевые моменты

### 1. Два источника новостей:
- **RSS Parser** - регулярные новости
- **Userbot** - инсайды из Telegram

### 2. Двухуровневая фильтрация:
- **Валидация** - проверка структуры данных
- **Приоритет** - определение важности

### 3. Умная публикация:
- Горячие новости → вне очереди
- Обычные новости → с учетом rate limiter

### 4. AI анализ:
- Для важных новостей (priority >= 6)
- Всегда для Insider новостей

### 5. Защита от ошибок:
- Декоратор `@safe_task` защищает все задачи
- AlertManager отправляет алерты админу
- Fallback на OpenAI если Gemini не работает
