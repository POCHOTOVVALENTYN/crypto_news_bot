### Детальный анализ кода:

#### 1.1. Проблема с именем модели

**Файл:** `services/ai_summary.py`, строка 42

**Текущий код:**
```python
model_name = 'gemini-1.5-flash'
```

**Проблема:** 
- Модель `gemini-1.5-flash` не найдена в API версии v1beta
- Согласно документации Google, правильное имя может отличаться

**Решение:**
- Попробовать другие варианты имен моделей
- Использовать `gemini-2.5-flash` или `gemini-1.5-flash-002`
- Проверить доступные модели через API

#### 1.4. Проблема в process_incoming_news

**Файл:** `services/ai_summary.py`, строка 179

**Текущий код:**
```python
if result and result.get('importance') == 'High':
    return result
return None
```

**Проблема:**
- Фильтрует только новости с `importance == 'High'`
- Но AI возвращает `importance` как строку: "High", "Very High", "Critical" и т.д.
- Это слишком строгая фильтрация

**Решение:**
- Использовать более гибкую проверку
- Проверять `importance_score` или несколько значений

---

#### 1.5. Проблема с priority для Insider новостей

**Файл:** `services/telegram_listener.py`, строка 228

**Текущий код:**
```python
priority=1  # Молния!
```

**Проблема:**
- Priority = 1 для Insider новостей - это неправильно!
- Должно быть priority = 10 (максимальный приоритет)
- Комментарий говорит "Молния!" но priority = 1 - это низкий приоритет

**Решение:**
- Изменить priority = 10

## 🔴 ПРОБЛЕМА 2: Userbot

### Из логов:

```
RuntimeError: 3 consecutive sign-in attempts failed. Aborting
TG_SESSION_STRING=None
```

### Детальный анализ кода:

#### 2.1. Проблема с миграцией сессии

**Файл:** `services/telegram_listener.py`, строки 33-74

**Проблема:**
- Миграция сессии выполняется при каждом запуске
- Если миграция не удается, возвращается пустая сессия
- Это приводит к запросу авторизации в интерактивном режиме

**Решение:**
- Упростить логику миграции
- Пропускать миграцию если она не работает
- Требовать ручную настройку сессии

---

#### 2.2. Проблема с интерактивной авторизацией

**Файл:** `services/telegram_listener.py`, строка 112

**Текущий код:**
```python
await self.client.start()
```

**Проблема:**
- `client.start()` требует интерактивного ввода (телефон, код)
- Это невозможно в фоновом режиме
- Нужна валидная сессия в `TG_SESSION_STRING`

**Решение:**
- Убедиться что сессия валидна перед запуском
- Не запускать если нет валидной сессии
- Предоставить инструкции для создания сессии

---

#### 2.3. Проблема с обработкой ошибок авторизации

**Файл:** `services/telegram_listener.py`, строки 158-164

**Проблема:**
- Ошибки авторизации логируются, но бот продолжает работать
- Нет четкого сообщения пользователю о том, что делать

**Решение:**
- Улучшить сообщения об ошибках
- Предоставить четкие инструкции
